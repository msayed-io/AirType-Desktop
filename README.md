# AirType

برنامج ويندوز أصلي (.NET 8 / WPF) يستقبل الكتابة الحيّة من تطبيق على هاتف Android عبر WebSocket محلي، ويدخلها **فورًا في الخانة النشطة حاليًا** على الكمبيوتر — أينما كان التركيز في تلك اللحظة.

## الفكرة في سطر
هاتفك يصبح لوحة مفاتيح حيّة للكمبيوتر، دون إنترنت، دون حسابات، دون AI، ودون تخزين أي شيء.

---

## التشغيل السريع

1. شغّل `AirType.exe`.
2. اضغط **«ربط هاتف»** — ستظهر نافذة فيها رمز QR ورمز PIN من 6 أرقام.
3. على الهاتف: اتصل بنفس شبكة Wi-Fi (أو نفس نقطة اتصال الهاتف)، وامسح الرمز من تطبيق العميل.
4. أدخل الـ PIN → يبدأ البث الحي.
5. اكتب على الهاتف — النص يظهر لحظيًا في أي خانة نشطة على الكمبيوتر (متصفح، وورد، تسك…)، **بما في ذلك العربية والإيموجي**.

### اختصارات عامة (قابلة للتعديل من الإعدادات)
| الاختصار | الوظيفة |
|---|---|
| `Ctrl+Alt+Shift+T` | تشغيل / إيقاف البث |
| `Ctrl+Alt+Shift+Q` | فتح نافذة الاقتران (QR) |
| `Ctrl+Alt+Shift+X` | **إيقاف طارئ** لكل الإدخال فورًا |

## كيف يعمل (بدون تشويق)

- **الاتصال**: خادم WebSocket مدمج داخل البرنامج (Kestrel) على منفذ قابل للتغيير (افتراضي 53017). يختار أول منفذ حر تلقائيًا إذا كان المنفذ مشغولًا. كل شيء بين الهاتف والكمبيوتر على الشبكة المحلية فقط.
- **الاقتران**: كل جلسة لها `Session ID` عشوائي + `PIN` من 6 أرقام + مفتاح سري داخلي لا يُعرض أبدًا. رمز QR يحمل عنوان الشبكة والمنفذ والجلسة فقط — **بدون أي أسرار**. هاتف واحد فقط لكل جلسة.
- **البروتوكول**: رسائل JSON عبر اتصال WebSocket دائم (`text_edit` تحمل `revision` و`deleteCount` و`insertText`). أي رسالة مكررة أو قديمة تُتجاهل. أي **فجوة في الترتيب** تجعل البرنامج يطلب `reset_stream` من الهاتف بدل كتابة نص خاطئ أبدًا.
- **الإدخال**: عبر `SendInput` بمفتاح `KEYEVENTF_UNICODE` — يدعم العربية والإنجليزية والرموز والإيموجي وسطر جديد. **لا يُستخدم الحافظة (clipboard) إطلاقًا**.
- **التركيز**: البرنامج لا يحفظ أي مقبض (handle) لأي خانة. عند وصول كل عملية إدخال، تذهب إلى العنصر الذي يملك التركيز **في تلك اللحظة** — لا أكثر ولا أقل.

## حماية النص (أهم ميزة)

- يعمل البث في الخلفية باستمرار، ويمكنك النقر على أي خانة إدخال ونقل التركيز بينها بصورة طبيعية دون إيقاف الاتصال. استخدم زر الإيقاف أو الاختصار العام عندما تريد إيقاف البث يدويًا.
- إذا كان البرنامج الهدف يعمل بصلاحيات Administrator أعلى من AirType، يمنع ويندوز (UIPI) تمرير الإدخال إليه — البرنامج يعرض تنبيهًا واضحًا ولا يحاول تجاوز الحماية.
- عند اكتشاف فجوة في الرسائل: إيقاف + إعادة مزامنة، وليس نصًا خاطئًا.

## الخصوصية

- لا إنترنت، لا سحابة، لا حسابات، لا AI.
- السجل المحلي **يخفي محتوى النص المُبث افتراضيًا** (يسجل الطول فقط). تفعيل تسجيل المحتوى خيار يدوي غير موصى به، في الإعدادات.

## قيود معروفة

1. **جدار الحماية**: عند أول تشغيل للخادم، يطلب ويندوز السماح بالاتصال — اختر **«السماح» للشبكات الخاصة**. بدون هذا لن يصل الهاتف. الاتصال محلي بالكامل.
2. **البرامج المرتفعة الصلاحيات**: الإدخال لن يعمل داخل برنامج يعمل بمستوى مسؤول أعلى من هذا البرنامج (حماية ويندوز). شغّل البرنامج بالمستوى نفسه إن لزم.
3. **الهاتف والكمبيوتر يجب أن يكونا على نفس الشبكة المحلية** (Wi-Fi واحد أو نقطة اتصال الهاتف). الشبكات التي تعزل الأجهزة عن بعضها (Guest/AP Isolation) لن تعمل.
4. **الخانات التي تقرأ الإدخال بطريقة غير قياسية** (بعض الألعاب بـ Raw Input أو منافذ HID) قد لا تستقبل النص.
5. **VPN/الشبكات الوهمية**: البرنامج يتجاهل واجهات VPN تلقائيًا عند اختيار عنوان الشبكة، لكن وجود VPN قد يمنع الاتصال المباشر أحيانًا.

## البناء من المصدر

```
dotnet build -c Release
dotnet test                     # اختبارات البروتوكول والجلسات والإدخال
dotnet run --project src/LiveTypeBridge.App
```

### فحص ذاتي بدون واجهة
```
src\LiveTypeBridge.App\bin\Release\net8.0-windows\AirType.exe --selftest
```
يفحص كامل خط الأنابيب محليًا (خادم + اقتران + ترتيب رسائل + إبطال جلسات) دون كتابة أي حرف في تطبيقاتك. النتيجة في `%LOCALAPPDATA%\LiveTypeBridge\selftest-result.txt`.

### عميل اختبار من المتصفح
يوفر `tools/test-phone.html` عميل ويب بسيط يحاكي الهاتف (اقتران + بث حي) لتجربة البرنامج دون تطبيق Android.

## بنية المشروع

```
src/
  LiveTypeBridge.Core/       # المنطق: بروتوكول، جلسات، شبكة، إدخال، إعدادات، تشخيص
    Protocol/                #   رسائل JSON + محرك ترتيب revisions
    Pairing/                 #   جلسات الاقتران + QR
    Networking/              #   خادم Kestrel + إدارة اتصالات الهاتف
    Input/                   #   SendInput + مضخة البث + اختصارات عامة
    Settings/ Logging/ Diagnostics/
  LiveTypeBridge.App/        # واجهة WPF (عربي/إنجليزي RTL، ثيم حديث)
tests/LiveTypeBridge.Tests/  # اختبارات xUnit
tools/test-phone.html        # عميل اختبار للمتصفح
```

## الأخذ في الاعتبار

- البرنامج يعمل بصلاحيات المستخدم العادي (asInvoker) ولا يطلب admin.
- الجلسة تعمل 12 ساعة بحد أقصى، وتُبطل فورًا عند إنشاء جلسة جديدة أو ضغط «قطع الاتصال».
- إن أُغلقت نافذة QR قبل الاقتران تبقى الجلسة صالحة حتى انتهائها (يمكن إعادة فتحها من «ربط هاتف»).

## التثبيت والتحديث التلقائي

يُوزَّع التطبيق عبر **Velopack**. ملف التثبيت الرسمي هو `Setup.exe` الذي تنشئه GitHub
Releases، وليس ملف `AirType.exe` المنفرد؛ التثبيت عبر Setup هو ما يضيف hooks
والـ updater اللازمة للتحديث الآمن واستبدال النسخة بعد إغلاق التطبيق.

### إنشاء إصدار جديد

لا حاجة لإنشاء tag يدويًا ولا لتشغيل بناء ثانٍ. عند كل push ناجح إلى `main` يقوم
Workflow `Windows Desktop CI and Release` بقراءة الإصدار الأساسي، وإضافة رقم تشغيل
تلقائي، ثم ينفذ restore وbuild والاختبارات وpublish وVelopack وGitHub Release من
**نفس ناتج البناء**. لذلك يكون `Setup.exe` والإصدار المنشور مطابقين تمامًا للنسخة
التي اجتازت الاختبارات في ذلك التشغيل. طلبات Pull Request تُبنى وتُختبر فقط ولا تنشئ
إصدارًا عامًا.

### ملاحظة مهمة عن مستودع GitHub الخاص

فحص التحديث داخل التطبيق يستخدم GitHub Releases بدون تضمين أي token داخل البرنامج.
لذلك يجب أن يكون مستودع الإصدارات **Public** حتى يستطيع المستخدمون تنزيل التحديثات.
لا يجوز توزيع token داخل التطبيق للوصول إلى مستودع خاص. إذا بقي المستودع خاصًا، سيظل
البناء ورفع Releases يعملان للمالك، لكن التحديث التلقائي للمستخدمين لن يعمل حتى يُنقل
مصدر الإصدارات إلى مستودع عام أو إلى خدمة ملفات عامة.
